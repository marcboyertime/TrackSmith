# Tutor audio-intelligence architecture

Tutor has two deliberately separate routes. The deterministic local waveform specialist receives the exact hash-validated WAV bytes, decodes them with `WAVFile`, and uses `SourceAwareAudioAnalyzer`. Its output is `localMeasurement`, never model hearing. The optional OpenAI route records a `modelHeardWaveform` observation only after a successful, consented request with exact bytes; rejected credentials, timeouts, and malformed responses record no success claim.

Every `TutorAudioIntelligenceResult` retains capture ID/hash/source/instance/runtime/scope, provider/model/checkpoint, byte provenance and capture-binding status, task-specific calibration, observations, alternatives, limitations, runtime, cancellation/deadline, and failure. The local lab sends each generated exact WAV back through `LocalWaveformSpecialist`, then records the provider binding status and emitted local-observation identifiers per fixture. A task is calibrated only when that named production-provider path passed. It also exercises real-provider hash-mismatch and undecodable-WAV failure states. This confirms provider-path provenance and deterministic observation availability on synthetic fixtures, not perceptual direction, Tutor decision quality, whole-mix masking, subjective improvement, source separation, structure, model listening, or owner listening.

Before/after measurement requires persisted baseline identity and local metric evidence, plus a distinct, later, format-compatible capture from the same instance/runtime/source/scope and explicit musician confirmation that the edit was upstream of and observable at the TrackSmith tap. An accepted result stores matching metric identifier/before/after/delta/unit/boundary values. Without every condition, Tutor preserves the user outcome and marks comparison unavailable. A delta is local measurement only: it never proves hearing, whole-mix masking, causality, or subjective improvement.
